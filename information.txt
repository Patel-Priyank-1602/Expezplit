1. EXECUTIVE SUMMARY & CORE VALUE PROPOSITION
================================================================================
Expezplit solves a fundamental consumer financial problem: managing personal 
spending while seamlessly resolving shared group expenses without mathematical 
errors, manual exchange rate conversion math, or payment chasing awkwardness.

Core Problems Solved:
1. The "Who Owes Whom" Complexity: In group trips, shared apartments, or 
   dinners, multiple people pay for different items. Manual splitting leads to 
   N*(N-1) complex transfer paths. Expezplit simplifies this into the minimum 
   possible K <= (N-1) direct transfers.
2. Multi-Currency Friction: Group members spending across borders face currency 
   conversion confusion. Expezplit normalizes all expenses into a unified base 
   currency using live foreign exchange rates while allowing instant display 
   toggles.
3. Frictionful Debt Settlement: Users hate switching between expense apps, 
   banking apps, and messaging apps to share payment details. Expezplit 
   integrates native web QR code generation, browser camera scanning (html5-qrcode), 
   and deep-linked UPI payments (upi://pay).
4. Lack of Automated Follow-Ups: Chasing friends for unpaid dues is awkward. 
   Expezplit features a dedicated Node.js Nodemailer microservice that 
   automatically dispatches styled transactional email summaries and reminders.

3. SYSTEM ARCHITECTURE & DATA FLOW
================================================================================
Expezplit is built on a modern microservices architecture, dividing concerns 
between a high-performance Client UI (React 19 + Vite), Backend-as-a-Service 
(Supabase PostgreSQL + RLS), Authentication (Clerk), Exchange Rate Gateway 
(ExchangeRate API), and a Server-Side Microservice (Node.js Express + Nodemailer).

System Data Flow Pipeline:
1. User Identity & Security: User authenticates via Clerk OAuth / Email OTP. 
   Clerk produces a secure JWT containing userId and user profile data.
2. Database Requests: Client communicates directly with Supabase PostgreSQL over 
   HTTPS. PostgreSQL Row Level Security (RLS) policies enforce security.
3. Exchange Rate Fetching: Client queries ExchangeRate API for live conversion 
   rates against base currency (INR). Rates are updated every 5 minutes.
4. Group Operations: Creating a group generates a unique random 9-character 
   invite code. Members join via QR code, URL link, or camera scan.
5. Expense & Debt Calculation: Adding an expense inserts records into 
   'group_expenses' and 'group_expense_splits'. The greedy minimum cash flow 
   algorithm computes net balances and optimizes settlement transfers.
6. Notification & Email Dispatch: Adding an expense asynchronously triggers 
   in-app notifications and calls the Node.js Express backend to send 
   styled HTML email reminders via Nodemailer to all debtors.

5. MATHEMATICAL & ALGORITHMIC ENGINE
================================================================================
5.1 Greedy Minimum Cash Flow Algorithm (Debt Simplification)

Naive settlement in a group of N members requires up to N*(N-1)/2 transactions. 
Expezplit implements a Greedy Graph Settlement Optimization Algorithm to 
reduce transaction volume to at most N-1 transactions.

Mathematical Formulation:
1. Net Balance Calculation:
   For each member i, net balance B_i is:
   B_i = Sum(Amount Paid by i) - Sum(Amount Owed by i)
   Conservation of Money: Sum(B_i) = 0 for all i.

2. Partitioning:
   - Debtors D = { (i, |B_i|) | B_i < -0.01 }
   - Creditors C = { (j, B_j) | B_j > 0.01 }

3. Greedy Settlement:
   - Sort D in descending order of debt magnitude.
   - Sort C in descending order of credit magnitude.
   - While D and C are non-empty:
     * Pick max debtor d in D and max creditor c in C.
     * Settle amount S = min(debt_d, credit_c).
     * Output directed transfer: d -> S -> c.
     * Update: debt_d = debt_d - S, credit_c = credit_c - S.
     * If debt_d < 0.01, remove d from D.
     * If credit_c < 0.01, remove c from C.

Complexity Comparison:
- Naive Transactions: O(N^2) max transactions.
- Expezplit Greedy Engine: O(N) max transactions (at most N-1 transfers).
- Time Complexity: O(N log N) sorting phase.
- Precision Guard: epsilon = 0.01 margin guard against float rounding noise.


5.2 Live Multi-Currency Conversion Engine

Database canonical balance is stored in Base Currency (INR). Conversion formula:
- A_display = A_base * Rate_target
- A_base = A_display / Rate_target

Polling Interval: 5 minutes (300,000 ms).
Fallback Chain: Live ExchangeRate API -> LocalStorage Cache -> Static INR (1.0).


5.3 Predictive Expense Analytics Engine

1. Category Breakdown Share:
   Share_cat = (Sum(Category Expenses) / Sum(Total Expenses)) * 100%

2. Monthly Run-Rate Projection:
   P_end_month = (Spent_current_month / Current_day_of_month) * Days_in_month

3. Month-over-Month Percentage Change:
   MoM_Change = ((Spent_this_month - Spent_last_month) / Spent_last_month) * 100%

9. STEP-BY-STEP LOCAL SETUP & EXECUTION GUIDE
================================================================================
Prerequisites:
- Node.js v18.0.0 or higher
- npm v9.0.0 or higher
- Git installed
- Supabase account (PostgreSQL Cloud DB)
- Clerk account (Authentication)
- ExchangeRate-API key (exchangerate-api.com)

Step 1: Clone Repository & Install Dependencies
   git clone https://github.com/Patel-Priyank-1602/Expezplit.git
   cd Expezplit
   cd frontend && npm install
   cd ../backend && npm install

Step 2: Configure Environment Variables
   1. Create backend/.env:
      PORT=3001
      EMAIL=your-gmail-address@gmail.com
      APP_PASSWORD=your-16-character-gmail-app-password

   2. Create frontend/.env.local:
      VITE_CLERK_PUBLISHABLE_KEY=pk_test_your_clerk_publishable_key
      VITE_SUPABASE_URL=https://your-supabase-project.supabase.co
      VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
      VITE_EXCHANGE_RATE_API_KEY=your_exchangerate_api_key

Step 3: Run Database Scripts in Supabase SQL Editor
   Run scripts from frontend/ directory in order:
   1. supabase-schema.sql
   2. supabase-notifications.sql
   3. supabase-upi.sql
   4. supabase-avatar.sql & supabase-avatar-policy.sql

Step 4: Launch Applications locally
   Terminal 1 (Backend Email Microservice):
      cd backend
      node emailServer.mjs
      (Server runs on http://localhost:3001)

   Terminal 2 (Frontend React App):
      cd frontend
      npm run dev
      (App runs on http://localhost:5173)
